# velog 2편 — 동기화 없는 기억 설계: 서버 없이 기억을 기계 사이로 옮기기

> 이 글은 [1편](https://velog.io/@cho4639/memdex-claude-codex-shared-memory)의 후속입니다.
> 태그: MCP, AI에이전트, SQLite, 시스템설계, 오픈소스

기억이 한 기계에만 있으면 반쪽입니다. 노트북에서 알아낸 것을 데스크톱 세션이 다시 알아내야 하니까요. 그런데
이걸 위해 서버를 두고 싶지는 않았습니다. memdex의 전제가 "SQLite 파일 하나, 데몬 없음, 네트워크 코드 없음"인데
동기화 하나 때문에 그걸 깨면 도구의 성격이 바뀝니다.

그래서 0.3.6에 들어간 것이 `export --sync` / `merge`입니다. 결론부터: **전송은 사용자가 이미 쓰는 폴더에
맡기고, memdex는 합치는 규칙만 정합니다.**

## 1. 선택지부터 지웠다

| 방식 | 왜 안 했나 |
|---|---|
| CRDT 서버 (실시간) | 서버·포트·인증이 필요해진다. 1인 개발 도구에 그 운영 부담은 값을 못 한다 |
| 클라우드 DB (Postgres 등) | 같은 이유 + 오프라인에서 죽는다 |
| 파일 하나를 통째로 동기화 | SQLite 파일을 Dropbox에 두면 두 기계가 같은 파일을 동시에 열어 손상된다 |
| **JSON 파일 여러 개 + 병합 규칙** | 전송은 git·Syncthing·공유 폴더가 이미 잘한다. memdex는 "무엇이 최신인가"만 정하면 된다 |

그래서 memdex가 하는 일은 두 가지로 줄었습니다. **내보낼 때 노트마다 파일 하나**, **합칠 때 마지막 쓰기 승리**.

## 2. uid: 기계마다 다른 id를 버리기

SQLite의 `id INTEGER`는 그 기계 안에서만 의미가 있습니다. A 기계의 3번 노트와 B 기계의 3번 노트는 남입니다.
스키마 v7에서 노트에 `uid`(uuid4)를 붙였고, 이 값은 노트가 만들어질 때 한 번 정해지고 절대 바뀌지 않습니다.

```sql
uid TEXT, updated_at REAL   -- v7에서 추가, 기존 노트는 열 때 자동 백필
```

`export`는 `notes/<uid>.json`을 씁니다. 파일 이름이 곧 신분증이라, 두 기계가 같은 노트를 들고 있어도 merge가
"같은 노트"임을 알 수 있습니다.

## 3. 충돌: 필드 단위 대신 노트 단위

필드별 LWW(제목은 A, 본문은 B)를 하면 구현은 두 배, 이해는 네 배 어려워집니다. 노트는 보통 한 번에 고치기
때문에 **노트 전체를 `updated_at`으로 비교**합니다.

```bash
memdex export --sync ../shared      # 노트·요약을 JSON으로
memdex merge ../shared              # 다른 기계 것을 적용
# merged 3 new, 1 updated, 12 unchanged, 0 from another checkout
```

같은 노트를 양쪽에서 고쳤다면 늦은 쪽이 이기고, **진 쪽은 조용히 사라지지 않고 출력에 남습니다**
(`conflict on #a1b2c3d4 "…": kept incoming`).

## 4. 요약은 공짜로 합쳐진다

파일 요약은 sha256으로 키가 잡혀 있습니다. 같은 내용이면 같은 sha, 같은 요약입니다. 그래서 요약에는 충돌이
존재할 수 없고, merge는 "없으면 넣는다"만 하면 됩니다. 1편에서 강조한 "해시에 묶인 요약"이 여기서 값을 합니다.
경로가 아니라 내용이 키라서, 두 기계의 경로가 달라도 같은 파일이면 같은 요약입니다.

## 5. 일부러 동기화하지 않는 것

**claim(잠금)과 message는 내보내지 않습니다.**

- 잠금은 임차입니다. 기계가 꺼진 뒤에도 유효한 잠금은 데드락 생성기입니다. 다른 기계의 잠금을 신뢰하려면
  fencing token과 시계가 필요한데, 그건 이 도구가 하려는 일이 아닙니다.
- 메시지는 받는 세션이 그 기계에 없습니다.

`export`가 만드는 디렉터리에 `notes/`와 `summaries/`만 있는 이유입니다.

## 6. 아직 안 한 것 (의도적으로)

- **실시간 동기화**: 두 기계가 만났을 때 화해하는 방식입니다. 회의 중에 두 노트북을 번갈아 쓰는 시나리오는
  다루지 않습니다.
- **range-based set reconciliation**: 해시 집합이 조금 다를 때 O(log n)로 화해하는 기법(Meyer 2023)을
  설계 노트에는 적어 뒀지만, 지금은 파일 단위 전체 복사로 충분합니다. 노트가 수천 개가 되면 그때 넣습니다.
- **삭제 전파**: 지금은 노트 생성/수정만 합칩니다. 삭제를 합치려면 tombstone이 필요합니다.

## 7. 정리

기억을 기계 사이로 옮기는 데 서버는 필요 없었습니다. 필요한 것은 **변하지 않는 신분증(uid)**, **비교 가능한
시간(updated_at)**, 그리고 **내용이 키인 요약(sha)** 세 가지였습니다. 나머지는 사용자가 이미 신뢰하는 전송로에
맡겼습니다.

```bash
pipx install memdex-mcp
memdex export --sync ~/Dropbox/memdex-shared
memdex merge  ~/Dropbox/memdex-shared
```
