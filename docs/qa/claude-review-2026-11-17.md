# Claude 자동 검토 검증

2026-11-17 · memdex 작업 #129

사용자가 전달한 Shearwater 작업 #127 브리프와 Claude Desktop의 폴더 접근 거절 사례를
읽고, 진행 중인 에이전트가 검토 자료를 직접 전달하고 결과를 회수하는 기능을 구현했다.
작업 #127의 제품 검토 참여와 구분되는 memdex 자동화 작업이다.

## 구현과 사용

- MCP `review(question, files, task_id)` 및 `review_status(request_id)`를 추가했다.
- CLI `memdex review`와 `memdex review-status`에서도 같은 구현을 사용한다.
- 호출자는 현재 프로젝트의 열린 작업과 명시적인 파일 목록을 제공한다.
- 파일 내용과 해시를 저장한 후 백그라운드 워커가 로그인된 Claude Code를 실행한다.
- 도구, MCP 설정, 사용자 커스터마이징을 끄고 `--no-session-persistence`로 실행한다.
- 결과와 받은편지함 회신을 같은 SQLite 트랜잭션으로 저장한다.
- 동일 입력 재호출, 동시 제출, 중복 워커는 같은 요청/회신을 재사용한다.
- 원래 채팅의 native ID로 생성된 정확한 route에만 회신한다.
- 120초 모델 타임아웃, 시작 실패, 오류 응답을 처리한다. 상태 조회에서 240초 이상
  미확인된 작업은 interrupted 회신으로 종결한다. 불확실한 호출을 자동 반복하지 않는다.
- 완료 후 job payload에서 파일 전문을 제거하고 경로/해시를 보존한다.

## 실제 검증 결과

- Windows의 로그인된 Claude Code 2.1.325로 실제 호출을 2회 수행했다.
- 요청 #202 → 회신 #204, `reply_to=202`, `task #129`, 이 채팅 route에서 직접 수신했다.
  Claude가 중단된 워커 상태, npm 래퍼 타임아웃, 실패 안내, 폴링, 자료 보존을 지적했다.
  중단 상태의 받은편지함 기록, npm 래퍼의 직접 node 실행, 실패 재시도 안내,
  파일 전문 제거를 반영했다. 외부 채팅 알림은 호출 에이전트의 대기 방식으로 유지한다.
- 최종 코드의 요청 #205 → 회신 #206, `reply_to=205`, `task #129`를 MCP inbox에서 확인했다.
- 설치된 `memdex review-status 205 --agent gpt`에서도 동일한 완료 결과를 조회했다.
- 최종 요청 #205의 저장 payload에 파일 전문이 남지 않은 것을 읽기 전용 DB 조회로 확인했다.
- `python -B -m unittest discover -s tests` 전체 698개 통과.
- 신규 회귀 테스트 12개가 파일 스냅샷, 중복/동시 실행, 원래 채팅 가시성, 작업 경계,
  시작 실패, 모델 예외/타임아웃, 중단된 작업 회신, CLI/MCP 진입점, npm 직접 실행을 확인한다.
- `git diff --check` 통과.

## 남는 조건

- 기존 MCP 프로세스는 재연결 후 새 도구를 발견한다. CLI는 즉시 사용 가능하다.
- 호출 에이전트가 결과 수신까지 inbox와 review_status로 대기해야 한다.
- 로그인 만료/계정 사용량 제한에는 실제 계정 조치가 필요할 수 있다.
- 검토 파일은 현재 프로젝트 내부 UTF-8 텍스트 20개, 합계 200 KB까지다.
- 일반적인 인증 파일명은 거부하지만 모든 파일의 비밀값 유무를 보증하지는 않는다.
  호출 에이전트가 공유할 수 있는 자료만 선택해야 한다.
- 파일 전문 제거 뒤에도 SQLite WAL/백업에는 이전 바이트가 남을 수 있다.
- npm 래퍼 경로는 모의 테스트로 검증했고, 실제 왕복은 native claude.exe로 수행했다.
