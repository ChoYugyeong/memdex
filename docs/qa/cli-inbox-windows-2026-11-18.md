# CLI 수신함과 Windows 커밋 훅 QA

2026년 11월 18일 Windows 11, Python 3.12.10, Git for Windows 2.56.1에서
`python -m unittest discover tests`로 714개 테스트가 모두 통과했다.
현재 작업 트리로 빌드한 `memdex_mcp-0.4.2-py3-none-any.whl`도
빈 가상환경에 오프라인 설치해 별도 Git 저장소와 SQLite DB에서 실행했다.

| 시나리오 | 확인한 결과 |
|---|---|
| 환경변수로 A를 지정하고 `remember --path B`로 저장 | 메모는 B에서만 조회됐다. 다음 저장에서 경로를 생략하자 A에서만 조회됐다. |
| 같은 작업에 `post --task`와 `post --task-id`로 발송 | 두 표기 모두 수신함에 작업 제목과 본문을 전달했다. |
| 메시지 도착 후 `inbox --follow --peek` 실행 | 미리보기와 다음 일반 읽기에서 같은 메시지가 나왔다. 그다음 읽기에서 수신함이 비었다. |
| 출력 파이프의 읽기 쪽을 닫고 일반 수신과 대기 수신 실행 | 설치한 CLI는 두 경우 모두 종료 코드 120을 반환했다. 다음 정상 호출에서 각각 원래 메시지를 전달했다. 코드 120은 이 환경의 관측값이다. 회귀 테스트는 출력 실패 전파와 재수신을 검사한다. |
| 다른 수신자에게만 메일이 있는 상태에서 수신함 확인 | 일반 읽기는 마지막 확인 위치를 갱신했다. 미리보기는 위치를 유지했고, 다른 수신자는 자신의 메일을 읽을 수 있었다. |
| 잠긴 파일에 실제 `git commit` 실행 | Git이 셸을 시작할 수 없는 환경에서 `memdex hook install`이 Python 훅을 설치했다. 커밋 차단 메시지를 확인했고, 소유자가 잠금을 해제한 뒤 동일한 변경이 커밋됐다. |
| 설치한 CLI와 MCP 서버가 같은 DB 사용 | CLI에서 파일을 색인하고 함수를 찾았다. CLI에서 저장한 한글 제목의 메모를 MCP 표준 입출력 연결의 `search`로 조회했다. |

## 독립 검토

- Claude Opus 5.5의 프로젝트 범위·옵션 검토 답변을 기존 대화에서 확인했다.
  명시 경로와 환경변수 기본값 양쪽에서 저장·조회를 검사하고, 두 작업 옵션으로 실제 메시지를 보내는 테스트에 반영했다.
- DeepSeek 데스크톱은 대기 중 미리보기가 메시지를 소비하는 문제를 지적했다.
  미리보기 직후 같은 수신자로 일반 읽기를 수행해 검증했다.
- 로컬 Qwen 2.5 7B는 설치된 모델 가중치를 직접 로드해 코드 발췌를 검토했다.
  출력 버퍼의 `flush()`에서 실패를 발생시키자는 제안을 테스트에 반영했다.
  출력 실패 뒤에도 성공 종료할 수 있다는 모델의 예상은 실제 파이프 실험에서 재현되지 않았다.
