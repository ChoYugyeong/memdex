Author here. I run agents from several vendors on the same checkouts: Claude Code, Codex, the ChatGPT desktop app, DeepSeek Harness, and a local Qwen for reviews. The failure is rarely "the model forgot a fact". It is "the session that was doing task 7 ran out of context, nobody wrote down where it stopped, and the next agent redid half of it". Or two of them edited the same file in the same hour.

memdex started as a "token-saving shared memory" (cached file summaries, outlines, notes). Then I looked at what my own agents actually did with it over 19 days on one machine:

- 493 handoffs across 40 projects, 242 messages between agents, 241 tasks in the ledger
- 45 file summaries saved, and none of them ever served to save a later read
- of the 241 tasks, 215 were checked only by the agent that did them; 6 were checked by a different agent

So 0.5.0 is the version that believes the data. It is now a coordination tool:

- Handoffs that exist even when the agent forgets. When a Claude Code session ends or compacts without a handoff, a hook drafts one from evidence: the first request, the files its edit tools wrote, uncommitted paths, its open tasks, its last message. No model call; it is labelled (auto) and "not vouched for by the agent", and secret-looking paths are dropped. Other agents run memdex handoff --auto.

- "Done" is a claim until someone checks it. Tasks form a tree with owners, blockers and evidence. A report is reported, the same agent checking it is self_verified, a different agent is verified, and a parent cannot be reported until its children are checked. Agent names are self-declared, so this is a cooperative record, not proof.

- Messages and locks. post/inbox with exact chat routes and reply_to; claim warns about overlaps, claim --exclusive locks, and a Claude Code PreToolUse hook refuses the edit itself (a git pre-commit hook refuses the commit). Each lock carries a fencing token and the file's sha.

- Cheap to keep connected. The server lists 10 tools by default, about 1,300 tokens of instructions and schemas per request (0.4.2 sent about 3,500). Code lookup, skills and AI review are opt-in with MEMDEX_TOOLS; unlisted tools stay callable.

- Boring on purpose. One SQLite file in ~/.memdex, Python standard library only, the MCP stdio protocol written by hand. memdex connect writes the entry into the clients you have (Claude Code, Codex, Cursor, VS Code, Windsurf, Zed, Cline, Gemini CLI, Claude Desktop, DeepSeek Harness); a model with no MCP client joins through the CLI with MEMDEX_AGENT=name.

What it is not, and what to use instead: one agent remembering its own sessions is claude-mem's job; a dependency-aware tracker synced across machines is beads; the widest feature set in this exact space is Memorix (Node, much larger). memdex is the small, single-machine, cross-vendor one. There is no server: two machines reconcile through a directory you sync. Only Claude Code has the session-end hook today.

793 tests, CI on Linux/macOS/Windows x Python 3.9/3.13, MIT, one maintainer. I'd especially like to hear from people running two or more agents on one repo: what goes wrong for you that this does not cover?

pipx install memdex-mcp (or uvx memdex-mcp), then memdex connect --agent claude.
