Author here. I run more than one coding agent on the same checkout - Claude Code, Codex, sometimes Cursor or a
local model. Two things kept hurting:

1. Each session starts from zero and re-reads the same files, so I pay for the same context over and over.
2. The agents can't see each other. Two of them edit src/store.py in the same hour and I find out from git diff.

memdex is a small MCP server that fixes both, and it is deliberately boring:

- One SQLite file in ~/.memdex, no daemon, no embedding API, no vector DB. Zero runtime dependencies; the MCP
stdio protocol is implemented directly against the standard library.

- Summaries are content-addressed. An agent reads a file once and saves 2-6 lines; the summary is keyed to the
file's sha256, so it stays valid until the bytes change and is flagged the moment they do. Worktrees of one
repo share the memory.

- Free outlines. Every indexed file gets a docstring/comment head plus classes and functions with line numbers
(Python via ast, 30+ other languages via per-language regexes - no tree-sitter). where_is replaces repetitive
grepping; read_snippet returns ~256 tokens around a match instead of the file.

- Coordinated, not locked. claim warns about overlapping edits with expiry, post/inbox carry messages, handoff is
what the next session sees first. claim --exclusive is a real lock, and two hooks enforce it: a git pre-commit
hook refuses a commit staging a locked file, and a Claude Code PreToolUse hook refuses the edit itself (exit 2,
with the reason printed for the model). It complements git; it does not try to replace it.

- Memory that ranks. Notes carry an ACT-R-style activation (uses decayed by time), pitfalls and decisions get a
prior, a few can be pinned into every brief, and notes nobody uses go cold - still stored and searchable, out of
the default context budget. Usage is attributed (notes read by another agent, re-confirmed after a change), and a
near-duplicate is flagged at save time with a 64-bit SimHash instead of being silently duplicated. Two strengths,
not one: storage strength (how often a note earned a confirm) keeps a well-learned decision in the brief even
when it was not needed this month, and superseding a note lowers its neighbours that share its files.

- Setup is one command. memdex connect writes the MCP entry into whichever of Claude Code, Claude Desktop, Cursor,
VS Code, Windsurf, Zed, Cline, Gemini CLI or Codex you actually have installed - merging one key, keeping the rest
of the file, saving a .bak - and --serve-check starts the server afterwards and speaks MCP to it, so a broken
setup fails there and not in the agent.

- A memory that outlives one machine. memdex export --sync DIR writes one JSON file per note and summary into a
directory you already sync; memdex merge applies it last-writer-wins and reports what it discarded. There is no
server and no network code: git, Syncthing or a shared folder is the transport.

- Not a cold start. memdex import turns the AGENTS.md / CLAUDE.md a repo already has into notes with refs, and
memdex digest hands an agent the notes that are two ways of saying one thing.

Measured on its own repo (72 files), memdex bench reports 156,063 tokens to read every file versus 10,446 tokens
of outlines - 93% smaller before a single summary is saved. That baseline is generous (a real agent greps and
reads slices), so the honest claim is smaller; the part that holds is that nothing gets rediscovered twice. Run it
yourself on any checkout: memdex bench --path .

What it is not: not a vector database (exact names beat embeddings for code; you can hand it vectors if you want
semantic search without a local model), not a real-time team service (sync is a directory two machines reconcile
when they meet), not a code navigator as precise as an LSP (outlines are regex-level).

363 tests, CI on Linux/macOS/Windows x Python 3.9/3.13. MIT. Happy to hear what breaks.

uvx memdex-mcp or pipx install memdex-mcp, then memdex connect --agent claude writes the MCP entry into the agents
you already have installed.
